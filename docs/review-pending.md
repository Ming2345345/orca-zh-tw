# 翻譯審查（第二位 agent）

翻譯 agent（antigravity）完成合併與機械式檢查後、開 PR 之前，必須由**另一位 agent** 審查。審查者不得是翻過該批次的 agent；目前指定由 Claude 擔任。

機械式檢查（`check_glossary.py`、`validate.py`）只能抓禁用詞、格式與插值；以下語意問題只有審查者能把關。

## 審查範圍

只審這次更新動到的條目，即分支與 `origin/main` 之間 `locales/zh-TW.json` 的差異：

```bash
git diff origin/main -- locales/zh-TW.json
```

條目很多時，`changed` 條目全審，`new` 條目至少抽查 30%（含所有 20 字以內的按鈕、選單、標題）。

## 審查項目

1. **語意**：譯文是否忠於目前 `en`；`changed` 條目是否仍殘留舊英文的意思。
2. **術語**：符合 `docs/zh-TW-glossary.md`，特別是 context（上下文／內容）、relay、skill、usage（用量／使用量）等需要語意判斷的詞。
3. **台灣用語**：沒有大陸用語或生硬的直譯腔。
4. **簡短度**：按鈕、選單、標題夠簡短，不會撐破介面。
5. **佔位符**：`{{...}}`、`{name}`、HTML 標籤、快捷鍵符號與 `en` 完全相同。
6. **一致性**：同一詞在本次與既有譯文中譯法一致。

## 處理方式

- 明確的錯誤（誤譯、漏譯、違反術語表）：審查者直接修正 `locales/zh-TW.json`，再重跑 `apply_glossary.py`、`check_glossary.py --pack`、`validate.py` 與單元測試，必須全部通過。
- 無法確定的譯法：不要猜，保留現狀並列入「待確認」。
- 不要擴大範圍去改本次更新以外的條目；發現既有問題只記錄 key 與原因。

## 審查報告

審查者回報以下內容，協調者將其貼進 PR 描述的「審查」一節：

- 審查者與被審查的翻譯 agent
- 審查條目數（`changed` 全審 X 條、`new` 抽查 Y／Z 條）
- 修正清單：key、舊譯、新譯、原因
- 待確認清單（沒有就寫「無」）
- 修正後四項檢查的結果

審查者無法完成或修正後檢查仍未通過時，PR 一律以 `--draft` 開出，並在最前面註明。
